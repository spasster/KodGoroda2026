# Контракт платформы

Единый источник правды для бэкенда, фронтенда и генератора данных. Если код расходится с этим файлом, прав файл. Менять контракт можно, но тогда в том же изменении правятся все стороны.

## Структура репозитория

```
survey/survey.json      анкета: роли, вопросы, шкала, парные вопросы
survey/signals.json     пороги сигналов
survey/quality.json     результаты проверки модели (необязательно, пишет отдельный скрипт)
survey/import_map.json  соответствие колонок Excel полям (создаёт бэкенд для формата data/sample)
data/generate.py        генератор тестового набора
data/sample/            interns.xlsx, mentors.xlsx, truth.json
backend/                FastAPI, SQLite, импорт, сигналы, приём анкет
frontend/               React + TypeScript + Vite
docs/design/            дизайн-система
docker-compose.yml, Makefile, .env.example
```

На финале МГТС выдаст свою анкету и свои таблицы. Тогда правятся `survey/survey.json`, `survey/import_map.json` и при необходимости `survey/signals.json`. Код под их данные меняться не должен.

## Анкета (`survey/survey.json`)

- `roles.intern` и `roles.mentor`: заголовок, подпись поля ID, список вопросов.
- Вопрос: `id`, `type` (`scale`, `text` или `choice`), `text`. Текстовых вопросов на роль может быть несколько. `choice` (да/нет, выбор из списка) сохраняется как текст и не входит ни в индекс, ни в разбор текста. Варианты лежат в `options` вопроса; без них форма `/form` показывает «Да» и «Нет». Ответ уходит в `answers` под `id` вопроса, ответ необязательный.
- `scale`: общая шкала для всех вопросов типа `scale` (`min`, `max`, подписи краёв).
- `paired_questions`: какие вопросы стажёра и наставника сравниваются напрямую.
- `months`: длительность программы.
- `first_month` (необязательно, `"2026-06"`): первый месяц программы. Нужен, если в выгрузке месяц задан датой или названием, а в файле нет самой первой анкеты.

## Формат Excel (`data/sample`, имитация выгрузки из Tabs)

Два файла, лист `Ответы`, одна строка на одну заполненную анкету.

`interns.xlsx`, колонки по порядку:

| Заголовок | Содержимое |
|---|---|
| `Отметка времени` | дата и время заполнения |
| `ID стажёра` | `S-01` … |
| `ID наставника` | `M-01` … |
| `Месяц стажировки` | 1…6 |
| текст каждого вопроса стажёра из `survey.json` дословно | число по шкале или текст |

`mentors.xlsx` такой же, но первыми идут `ID наставника`, `ID стажёра`, `Месяц стажировки`, дальше вопросы наставника.

Пропущенная анкета значит, что строки за этот месяц нет. Пустой комментарий значит пустую ячейку.

Импорт находит колонки так: сначала по `survey/import_map.json`, потом по совпадению заголовка с текстом вопроса (без учёта регистра, пробелов, переводов строк, пунктуации, `ё`/`е`). Строка заголовков ищется среди первых десяти строк, шапка с названием опроса и пустые строки выше неё не мешают. Пустые строки внутри пропускаются. Нераспознанные колонки попадают в отчёт импорта, импорт не падает. Поддерживаются `.xlsx` и `.csv`.

Если выгрузка отличается от `data/sample`:

- **Одна книга, два листа.** Лист, в названии которого есть «настав» или «стаж» (наставник проверяется первым), читается как таблица этой роли. Если в книге один лист с ответами, роль берётся из поля загрузки (`interns` или `mentors`, `--role` в CLI), имя листа её не меняет. Лист «Пары» (или `pairs`) задаёт пары: колонки с «стаж» и «настав» в заголовке, иначе первые две.
- **Пары без ID наставника в таблице стажёра.** Порядок поиска: лист «Пары», ключ `pairs` в `import_map.json` (`{"Стажёр 1": "Наставник 3"}`), одинаковый номер в конце ID («Стажёр 3» и «Наставник 3»; в отчёте будет предупреждение).
- **Месяц.** Число, «1 месяц», «2-й месяц», «Месяц 3» берутся как номер. Дата или текст вида «Июнь 2026», «06.2026» превращаются в номер от первого месяца в файле, либо от `first_month` из `survey.json`. Без `first_month` самый ранний месяц считается по всем таблицам одного импорта вместе.
- **Шкала не 1–5.** Меняются `scale.min` и `scale.max`. Из ячейки берётся первое число: «4 - скорее да», «5 – отлично». Ответ без числа пропускается с предупреждением.
- **Длинный формат** (строка на ответ). В `import_map.json` колонке с текстом вопроса ставим `"question"`, колонке с ответом `"answer"`. Строки сворачиваются в анкету по распознанным колонкам `intern_id`, `mentor_id` и `month`; остальные колонки («ID ответа», время) в ключ не входят. Тексты вопросов должны совпадать с `survey.json` или быть в `import_map.json`.
- **Колонки «Месяц N. вопрос»** (также «N месяц - вопрос»): одна строка на человека разворачивается в строку на месяц, пустые месяцы пропускаются. Дополнительных ключей не нужно.
- В длинном формате и при колонках по месяцам номера строк в отчёте условные.
- Ненужную колонку выключает `"Название колонки": null` в `import_map.json`.

## Хранение (SQLite)

- `pairs(pair_id, intern_id, mentor_id)`. `pair_id` строится из ID стажёра: `S-03` → `P-03`. Если такой `pair_id` занят другим стажёром (`A-1` и `B-1`), берётся `P-` и ID стажёра целиком. Символы `/`, `:` и пробел в `pair_id` заменяются на `-`. Пара один к одному.
- `responses(id, pair_id, role, person_id, month, source, submitted_at, created_at)`. `source`: `excel`, `form`, `yandex`, `gsheet`. Уникальность по `(pair_id, role, month)`, повторная анкета заменяет прежнюю.
- `answers(response_id, question_id, score, text)`.
- `reviews(signal_key, status, note, updated_at, month)`. Ключ — ситуация. `month` — последний месяц самой ситуации (`signal.month`) на момент отметки. В старой базе колонку добавляет `ALTER TABLE` при запуске.
- `text_cache(text_hash, analyzer, result_json)`.

Сигналы и ситуации не хранятся: данных мало, они пересчитываются при каждом запросе. Кэшируется только разбор текста.

## Индексы

- Индекс роли за месяц — среднее всех ответов типа `scale` этой роли. Нет анкеты, значит `null`.
- Нормированный индекс: `(index - min) / (max - min)`, от 0 до 1. Пороги в `signals.json` заданы в долях размаха шкалы.
- Разрыв за месяц: `gap = mentor_index - intern_index` в баллах шкалы. Положительный — стажёру хуже, чем видит наставник.
- Пороги сигналов считаются по точным индексам. В ответах API (`Cell.gap`, тексты сигналов) разрыв равен разнице уже округлённых индексов: оценки 4,4 и 4,8 дают разрыв 0,4, даже если точная разница 0,35.

## Разбор текста

Интерфейс в `backend/app/analyzer/`:

```python
def analyze(text: str, role: str, question_id: str) -> TextInsight
# TextInsight: sentiment: float (-1..1), topics: list[str], concerns: list[{label, quote}], summary: str | None
```

- `rules` (по умолчанию): словарь русских ключевых слов и основ. Работает без сети и модели.
- `openai`: OpenAI-совместимый клиент (Ollama с Qwen локально или внешний API), включается `LLM_PROVIDER=openai`. Промпт и схема ответа лежат в `backend/app/analyzer/llm.py`, их дорабатывает ML.
- Каждая цитата проверяется функцией `verify_quote(quote, text)`: точное вхождение после нормализации (регистр, пробелы, `ё`/`е`, кавычки), длина не меньше `quote_min_length`. Не прошла проверку — цитата и основанный на ней вывод отбрасываются. Позиции `start`/`end` считаются по исходному тексту, в ответах API в кодовых единицах UTF-16, как `String.prototype.slice` в JS: эмодзи перед цитатой не сдвигают подчёркивание.

Темы (`topics`): `tasks_shortage` нехватка задач, `overload` перегрузка, `mentor` отношения с наставником, `clarity` непонятные задачи, `motivation` мотивация и интерес, `team` команда, `growth` рост и обучение, `positive` хорошее.

## Сигналы

Бэкенд считает месячные сигналы: условие сработало в конкретном месяце. Наружу API отдаёт **ситуации**: все месячные сигналы одного типа у одной пары и роли склеены в одну запись. Месячные сигналы остаются внутри: по ним считаются статус клетки месяца и эталон `data/truth.json`.

Тип, условие, важность месячного сигнала. Пороги из `survey/signals.json`.

| `type` | Условие | `role` | Важность |
|---|---|---|---|
| `decline` | нормированный индекс роли упал на `two_month_drop` и больше два месяца подряд или на `single_drop` за месяц | `intern` или `mentor` | `high` за резкий спад, иначе `medium` |
| `gap_intern_low` | `gap / размах >= min_gap`: стажёру хуже, чем видит наставник | `both` | `high`, если `>= high_gap` или разрыв растёт второй месяц, иначе `medium` |
| `gap_mentor_low` | `-gap / размах >= min_gap`: наставник недоволен, а стажёр оценивает всё высоко | `both` | `medium`, `high` при `>= high_gap` |
| `low_question` | в анкете роли за месяц есть вопрос типа `scale` с нормированной оценкой `<= low_question.max_score` (по умолчанию 0,25: на шкале 1–5 это 2 и ниже). Один сигнал на анкету, даже если низких вопросов несколько | `intern` или `mentor` | `high`, если таких вопросов два и больше или оценка равна минимуму шкалы, иначе `medium` |
| `text_vs_score` | нормированный индекс роли `>= min_index`, а комментарий той же анкеты с `sentiment <= max_sentiment` или с темой из `tasks_shortage`, `overload`, `mentor` | `intern` или `mentor` | `medium`, `high` для темы `mentor` |
| `silence` | (а) нет анкеты за месяц, хотя у второй стороны пары она есть или месяц уже прошёл для остальных пар; (б) комментарий пуст, хотя в прошлые месяцы был; (в) длина комментария упала на `length_drop` против среднего прошлых при среднем `>= min_prev_length`; (г) все оценки анкеты одинаковые три месяца подряд | `intern` или `mentor` | (а) `high`, если у той же роли анкеты нет и в предыдущем месяце или в предыдущем месяце у неё сработал `decline`, иначе `low`; остальное `low` |

Как читать условия. Бэкенд и эталон `data/expected.py` считают одинаково:
- Спад за два месяца: индекс падал в каждом из двух месяцев, а в сумме упал на `two_month_drop` и больше. Ряд 4,6 → 4,4 → 3,8 даёт сигнал, ряд 4,4 → 4,2 → 4,0 не даёт.
- Пропущенная анкета ряд не рвёт. Серия ситуации (`since_month`) тоже: месяцы, где у роли ситуации нет анкеты (у разрыва нет анкеты хотя бы одной стороны), при поиске начала серии пропускаются. Спад считается от прошлой анкеты той же роли, рост разрыва от прошлого месяца, где ответили обе стороны.
- «Разрыв растёт второй месяц»: разрыв больше прошлого, а прошлый больше позапрошлого. Прошлые разрывы могут быть ниже `min_gap`.
- Молчание (а): месяц прошёл, если по нему есть хотя бы одна анкета у каждой из остальных пар.
- Молчание (в): средняя длина считается только по непустым прошлым комментариям.
- Молчание (г): в каждой из трёх анкет подряд все оценки одинаковые. От анкеты к анкете оценка может меняться.
- Текст против оценки: хватает одного комментария с проверенной цитатой и тональностью не выше `max_sentiment` или с темой из списка. Пометка спорной разметки `sure: false` в `data/scenarios.py` сигнал не отменяет.
- Низкая оценка по вопросу: берутся только вопросы типа `scale`, оценка сравнивается с порогом после нормировки.
- Активные месяцы отсчитываются от последнего месяца, по которому у пары есть анкета.

### Ситуации

Ситуация = все месячные сигналы одного `type`, `pair_id` и `role`. Ключ ситуации стабилен и без месяца: `{type}:{pair_id}:{role}`. Месячный сигнал внутри имеет ключ `{type}:{pair_id}:{role}:{month}`, наружу он не выходит, кроме `data/truth.json`.

- `month` — последний месяц, когда сработало; `months` — все такие месяцы по возрастанию; `since_month` — начало последней непрерывной серии месяцев, которая кончается на `month`.
- `active`: `month` входит в последние `active_months` месяцев пары и статус не `rejected`. Подтверждённая ситуация остаётся активной, отклонённая нет.
- `severity`: самая высокая важность среди месячных сигналов в окне активных месяцев. Если ситуация не активна, важность последнего месяца.
- `title`, `action`, `values` берутся от последнего месячного сигнала. `explanation` тоже, а если серия длиннее одного месяца, в конец добавляется «Повторяется с 3-го месяца, 2 мес. подряд.» Число считается по месяцам срабатывания внутри серии
- `quotes` собираются из месячных сигналов: свежие месяцы первыми, без повторов, не больше 3.
- Статус пары по активным ситуациям: `risk`, если есть ситуация с `high`, которая держится два месяца и больше (`month > since_month`), или ситуаций с важностью `medium` и выше две и больше; `watch`, если есть хотя бы одна активная; иначе `ok`. Статус клетки месяца считается по месячным сигналам по другому правилу: `risk`, если есть `high` или сигналов два и больше; `watch`, если один; иначе `ok`. Клетка считает месячные сигналы этого месяца без учёта `active_months`; месячные сигналы отклонённой ситуации в клетке не считаются.
- `Cell.signal_keys` — ключи ситуаций, которые сработали в этом месяце. `highlights[].signal_key` — ключ ситуации.
- `open_signals`, `totals.open_signals`, `totals.confirmed`, `totals.rejected` считаются по ситуациям.

### Отметка HR

HR отмечает ситуацию целиком: «Проблема подтвердилась» (`confirmed`) или «Проблемы нет» (`rejected`). Вместе со статусом запоминается `review.month` — последний месяц самой ситуации на момент отметки, а не последний месяц пары: анкеты других ролей за более поздний месяц не прячут новое срабатывание.

**Повтор после отметки «Проблемы нет».** Если статус `rejected`, а ситуация сработала в месяце позже `review.month`, статус снова `open`, а `review.previous = {status: 'rejected', month}`. Заметка остаётся. Новая отметка HR убирает `previous`. У `confirmed` статус не меняется.

**Что изменилось после отметки (`outcome`).** Заполняется, если статус `confirmed` (или есть `review.previous`) и у пары есть анкеты за месяц позже `review.month`. Иначе `null`. `repeated`: ситуация сработала в месяце позже `review.month`. `text` по типу:
- разрывы: «После отметки в 4-м месяце разрыв сократился: 1,8 → 0,6», «…разрыв вырос: 1,8 → 2,2», «…разрыв не изменился: 1,8» (модуль разрыва в месяце отметки и в последнем месяце, где ответили обе стороны);
- `decline`, `low_question`: «После отметки в 4-м месяце оценка стажёра выросла: 3,0 → 4,2», «…упала: …», «…не изменилась: 3,0» (индекс роли в месяце отметки и в последнем месяце с её анкетой);
- `text_vs_score`, `silence`: «После отметки в 4-м месяце повторилось в 5-м» или «После отметки в 4-м месяце не повторялось».

Значения сравниваются после округления до одного знака. Если для сравнения нет значения (нет анкеты в месяце отметки), берётся формулировка «повторилось / не повторялось».

### Тексты

Каждый сигнал содержит понятный HR текст на русском:
- `title`: что произошло, коротко. Пример: «Стажёр оценивает стажировку всё ниже». Для молчания (а): «От стажёра нет анкеты за 5-й месяц», а если вторая сторона месяц ещё собирается, «Стажёр ещё не прислал анкету». К объяснению молчания (а) с важностью `high` в конец добавляется причина: «Анкеты нет второй месяц подряд.» или «Перед этим оценки стажёра падали.»
- `explanation`: одно-два предложения с цифрами. Пример: «Оценка стажёра за три месяца: 4,6 → 3,8 → 3,0».
- `action`: что сделать HR. Пример: «Поговорить со стажёром один на один: что изменилось с 3-го месяца».

Месяц в текстах пишется цифрой, как в таблице дашборда: «в 5-м месяце», «с 3-го месяца». Для второго месяца предлог другой: «во 2-м месяце», «со 2-го месяца». Число между стажёром и наставником везде называется «разрыв».

## API

Префикс `/api`, JSON, время в ISO 8601 UTC. Числа индексов округляются до одного знака.

Типы (TypeScript, фронт держит их в `src/api/types.ts`):

```ts
type Role = 'intern' | 'mentor'
type SignalType = 'decline' | 'gap_intern_low' | 'gap_mentor_low' | 'low_question' | 'text_vs_score' | 'silence'
type Severity = 'high' | 'medium' | 'low'
type PairStatus = 'risk' | 'watch' | 'ok'
type ReviewStatus = 'open' | 'confirmed' | 'rejected'

interface Quote { role: Role; month: number; question_id: string; text: string; start: number; end: number }
// Одна ситуация: все месячные срабатывания одного типа у пары и роли
interface Signal {
  key: string                  // `{type}:{pair_id}:{role}`, без месяца
  type: SignalType; pair_id: string; role: Role | 'both'
  month: number                // последний месяц, когда сработало
  months: number[]             // все месяцы, когда сработало
  since_month: number          // начало последней непрерывной серии, которая кончается на `month`
  severity: Severity
  title: string; explanation: string; action: string
  values: { role: Role; month: number; value: number | null }[]
  quotes: Quote[]
  active: boolean
  review: {
    status: ReviewStatus; note: string | null; updated_at: string | null
    month: number | null                                       // месяц, когда поставлена отметка
    previous: { status: ReviewStatus; month: number } | null   // «проблемы нет», после которой сработало снова
  }
  outcome: { review_month: number; last_month: number; repeated: boolean; text: string } | null
}
interface Cell {
  month: number; intern_index: number | null; mentor_index: number | null; gap: number | null
  status: PairStatus; signal_keys: string[]; missing: { intern: boolean; mentor: boolean }
}
interface PairSummary {
  pair_id: string; intern_id: string; mentor_id: string; status: PairStatus; last_month: number
  intern_index_last: number | null; mentor_index_last: number | null
  trend: 'up' | 'down' | 'flat'; open_signals: number; cells: Cell[]
}
interface Overview {
  updated_at: string; months: number[]; scale: { min: number; max: number }
  totals: { pairs: number; risk: number; watch: number; ok: number; open_signals: number; confirmed: number; rejected: number; responses: number }
  pairs: PairSummary[]
  recent: { at: string; pair_id: string; role: Role; person_id: string; month: number; source: string }[]
}
interface CommentItem {
  role: Role; month: number; question_id: string; question_text: string; text: string
  sentiment: number | null; topics: string[]; highlights: { start: number; end: number; signal_key: string }[]
}
interface MethodSignal {
  type: SignalType; name: string
  how: string; why: string[]; action: string; limit: string; source: string | null
  open: number; confirmed: number; rejected: number    // ситуаций сейчас
}
interface Method {
  principles: string[]; signals: MethodSignal[]; baseline: string
  quality: object | null     // survey/quality.json как есть
}
interface PairDetail extends PairSummary {
  series: { month: number; intern_index: number | null; mentor_index: number | null
            intern: Record<string, number | null>; mentor: Record<string, number | null> }[]
  comments: CommentItem[]
  signals: Signal[]
}
```

Приём анкеты `POST /api/ingest`:

```json
{ "role": "mentor", "person_id": "M-03", "month": 6,
  "answers": { "overall": 3, "speed": 2, "independence": 3, "engagement": 3, "comment": "..." },
  "source": "form" }
```

- Пара находится по `person_id`. Для нового стажёра можно передать `intern_id` и `mentor_id`, тогда пара создаётся.
- Оценки проверяются по шкале, лишние ключи игнорируются, неизвестный вопрос в ответе не ошибка.
- Ответ: `{ response_id, pair_id, replaced: bool, new_signals: Signal[] }`, где `new_signals` — ситуации, которых не было до этой анкеты, и ситуации, у которых после неё появился новый месяц в `months`.
- Ошибки: 422 с `{detail}` на русском.

Вебхук Яндекс Форм `POST /api/ingest/yandex` принимает плоский JSON: `role`, `person_id`, `month` и ответы, где ключ — `id` вопроса или его текст. Значения могут быть строками. В Яндекс Формах в разделе «Интеграции» настраивается HTTP POST на `<адрес>/api/ingest/yandex` с телом-шаблоном из переменных ответов. Пример тела лежит в `docs/integrations.md`.

События `GET /api/events` (SSE), каждые 15 секунд комментарий `: ping`:
- `event: response`, `data: {pair_id, role, person_id, month, source, new_signal_keys}` (ключи ситуаций, как в `new_signals`)
- `event: review`, `data: {key, status}`
- `event: reset`, `data: {}`

## Экраны фронта

Интерфейс один, для HR, на русском. Светлая и тёмная тема, переключатель запоминается.

- `/` Обзор: итоги, таблица «пара × месяц», активные сигналы, последние поступления.
- `/pairs/:id` Карточка пары: две линии индексов, ответы по вопросам, комментарии с подсвеченными цитатами, сигналы с действием и отметкой.
- `/signals` Сигналы: очередь «с кем поговорить», фильтры по статусу и важности, отметка «Проблема подтвердилась» или «Проблемы нет».
- `/method` Как считаем: принципы, по каждому сигналу формула, причины и ограничения, результаты проверки модели (`GET /api/method`).
- `/form` Форма для стажёра и наставника: собирается из `/api/survey`, удобна с телефона, без навигации дашборда.

Новый ответ, пришедший через SSE, виден без перезагрузки: обновляются данные и показывается уведомление.

### Раннее предупреждение и эффект

Базовый способ: HR смотрит среднюю оценку за один месяц и реагирует, когда она ниже `baseline.index_below` (по умолчанию 0,625, на шкале 1–5 это 3,5). Порог в нормированном индексе, сравнение строгое.

`early[]` — пары, у которых есть хотя бы одно срабатывание, не снятое отметкой «Проблемы нет» (месяцы до отметки у повторившейся ситуации тоже не считаются):

```ts
interface Early {
  pair_id: string; intern_id: string; intern_name: string | null
  first_signal_month: number       // первый месяц срабатывания
  risk_month: number | null        // первый месяц, когда статус пары на конец месяца был risk (те же правила, что у статуса пары, по срабатываниям до этого месяца)
  baseline_month: number | null    // первый месяц, когда индекс стажёра или наставника ниже порога
  lead_months: number | null       // baseline_month - first_signal_month; null, если базовый способ не сработал
}
```

Блок `effect` в ответе аналитики:

```ts
effect: { pairs_with_signals: number; earlier: number; same_or_later: number; invisible: number
          avg_lead: number | null; baseline_score: number }
```

`earlier` — пар с `lead_months > 0`; `same_or_later` — с `lead_months <= 0`; `invisible` — пар, где базовый способ не сработал совсем; `avg_lead` — среднее `lead_months` по парам, где он не `null`, один знак; `baseline_score` — порог в баллах шкалы.
